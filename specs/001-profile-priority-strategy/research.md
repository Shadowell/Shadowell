# Research: Profile Priority and Paper Strategy

## Decision: Use a three-stage profile narrative

- **Decision**: Present big-data primary profession first, ongoing side research second, and
  verified outcomes/capability evidence third in both languages.
- **Rationale**: This directly encodes the user's requested professional hierarchy and avoids the
  current AI-first interpretation.
- **Alternatives considered**: Merely moving the existing big-data block upward was rejected because
  the AI-first title and opening table would still contradict the intended hierarchy.

## Decision: Treat the README image as static

- **Decision**: Correct the caption so only the linked dashboard claims a 60-second refresh. Recapture
  the image after switching when practical, but never label the embedded PNG as live.
- **Rationale**: GitHub README stores a repository PNG; the browser poller runs only on GitHub Pages.
- **Alternatives considered**: A cache-busted PNG cannot self-update, and exposing a dynamic image
  renderer would reintroduce an unnecessary public contract.

## Decision: Switch only the protected BitPro alias

- **Decision**: Use the validated settings route to map `github-profile` to the uniquely matched
  running Paper strategy 480, then compare pre/post Paper snapshots and public response fields.
- **Rationale**: The mapping contract validates the target session and changes only one app setting.
- **Alternatives considered**: Editing Shadowell's public URL would expose identity and fork the stable
  contract; changing Paper configuration or lifecycle is outside scope and prohibited.

## Decision: Preserve the existing visual system

- **Decision**: Keep the compact dark financial dashboard and spend the design change on information
  architecture and truthful labeling rather than decorative restyling.
- **Rationale**: The user's complaint is hierarchy and stale interpretation, not the dashboard's
  established visual language.
- **Alternatives considered**: A full restyle would add risk without improving the requested message.
